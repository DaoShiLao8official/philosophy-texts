# 哲学文本

用于整理哲学创作、译稿与阅读笔记，并保留每次修订的记录。

## 目录

| 目录 | 用途 |
| --- | --- |
| `writings/` | 原创文章、论证草稿与随笔 |
| `translations/` | 译稿、原文出处、术语表与翻译说明 |
| `notes/` | 阅读笔记、问题记录与参考文献 |
| `templates/` | 创作、翻译和笔记模板 |

## 添加一篇文本

1. 复制相应模板到对应目录，以简短标题命名，例如 `writings/论理由与责任.md`。
2. 长篇作品使用独立文件夹，按章节拆分；译稿可将术语表放在同一文件夹。
3. 每次完成一组相关修改后提交，说明改了什么，例如“补充第二节的反例”或“统一 Bedeutung 的译法”。
4. 需要讨论的问题可记录在 GitHub Issues；一次较大的修订也可以通过 Pull Request 对照审阅。

## 文本格式

没有 Word 源文件的文章可以直接以 UTF-8 编码的 Markdown（`.md`）保存。有同名 Word（`.docx`）的文章以 Word 为准，Markdown 由仓库自动生成。

## Word 自动同步

将新增或修改的 `.docx` 上传到 `main` 分支后，GitHub Actions 会在同级目录生成或更新同名 `.md`，并自动提交。脚注、表格、公式及图片会随正文转换，图片保存到所属顶级目录的 `_media/` 中。原 Word 文件保持不变，Word 的分页与版式不对应 Markdown 的网页排版。

请在 Word 中修改正文；直接编辑自动生成的 Markdown，会在下一次同步时被 Word 内容覆盖。只修改电脑本地的文件不会触发同步，仍需把新版上传到 GitHub。

Word 改名、移动或删除后，会清理同步记录中旧的 Markdown；如果旧 Markdown 已被手动修改，则保留该文件，并在日志中提示。独立的 Markdown 文章和目录说明不会被删除。旧图片保留，避免破坏其他文章的引用。

在仓库的 **Actions → Word → Markdown 自动同步** 中可查看运行结果；需要手动重新同步时，点击 **Run workflow** 并选择 `main`。转换失败时不会发布本轮转换结果，可在日志中查看出错文件。

在引用和译稿中记录原文版本、页码或章节，以及可用的来源链接。阅读笔记应区分原文引述、转述和自己的解释。对尚未确定的术语或论证，保留待讨论标记。

## 版本与发布

正文开头注明状态：草稿、修订中或定稿。完成一轮重要修订后，可以添加 Git 标签，例如 `2026-10-文章短名-v1`，便于回到当时的版本。

本仓库为公开仓库，提交内容和历史修订均可能被公众查看。请仅提交你希望公开的文本。
